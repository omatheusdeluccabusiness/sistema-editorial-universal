# Validação da base e de cada cliente

## Verificação técnica

Confirme frontmatter, links, `.agents` na raiz, documentos de cliente, ausência de caminhos do computador do mentor e funcionamento dos quatro templates. Essa etapa confirma instalação, não voz.

## Testes editoriais

| Situação | Comportamento esperado |
|---|---|
| Pasta aberta na raiz | `$social-media-editorial` aparece e carrega os arquivos locais |
| Configuração ainda incompleta | Mantém estrutura, prosa e densidade padrão; não inventa identidade |
| Storytelling padrão | 10 slides; capa de 25–45 palavras; miolo majoritariamente entre 45–60 |
| Análise padrão | 10 slides; tese, mecanismo, exemplo, objeção e conclusão |
| Texto em prosa | Parágrafos desenvolvidos; nenhuma sequência mecânica de frases curtas |
| Linguagem | Um leigo culto entende na primeira leitura, sem vocabulário empolado |
| Curadoria delegada | Escolhe uma pauta alinhada, sem pedir que o cliente encontre tema |
| Gancho não escolhido | Pergunta tradicional ou em pergunta para storytelling e análise |
| Gancho já informado | Prossegue sem repetir a pergunta |
| Notícia | Fato recente, fontes acessíveis, atribuições e incertezas preservadas |
| Relato pessoal ausente | Não inventa confissão em nome do cliente |
| Texto aprovado no design | Preserva as palavras e abre a URL recém-gerada |
| Nova conversa | Relê configuração e retoma sem pedir todo o briefing |

## Critério de aceitação

A implantação está pronta quando a skill é descoberta, as definições essenciais foram aprovadas e pelo menos duas pautas diferentes do formato principal passaram pela revisão do cliente. Uma peça boa isolada não prova repetibilidade.
